# Core reference

- 現在の要件を満たす最小の概念差分を選ぶ。
- 実装前に、要件解釈、既存パターン、変更ファイル、新規概念、schema 変更、不変条件、棄却案、承認事項、検証方法を decision diff として示す。
- decision diff に含まれない設計判断が実装中に発生したら、実装を止めて承認を求める。
- 新しいクラス、テーブル、カラム、状態、抽象化、依存、job、callback、設定を追加するときは、現在の要件に必要な理由と既存構造で代替できない理由を示す。
- 予測した将来要件、一般化、feature flag、見た目だけの周辺リファクタリングを現在の変更に混ぜない。
- 既存のローカルパターンを、抽象的なベストプラクティスより優先する。
- 保存するのは事実とし、既存の事実から導出できる状態を重複して保存しない。
- 最小差分を理由に、入力検証、認可、型の正確性、エラー処理などの security / correctness を削らない。
- 設計判断を含む行と機械的な行を分離し、レビューで判断の差分が見えるようにする。
- コミットはファイル単位ではなく意味単位で分け、同じ行を何度も書き換えない。
