# User-software reference

- ユーザーの目的と意思決定を中心に設計し、内部のモデルや実装都合をそのまま操作させない。
- ユーザーが今どの状態にいて、操作の結果どうなり、次に何ができるかを理解できるようにする。
- 成功時は結果と変更された状態を示し、処理中は待つ必要があることを示す。
- 失敗時は原因、影響、ユーザーが取れる復旧方法を示し、入力や作業内容を不必要に失わせない。
- 破壊的な操作や後戻りできない操作は、影響を明示してから実行し、可能なら取消しや復旧手段を用意する。
- 権限、データの所有者、公開範囲をユーザーが理解できる言葉と操作で扱う。
- 画面や API の都合で、同じ意味の状態や操作を場所ごとに別の概念として見せない。
- 先回りした機能や設定で現在のユーザー体験を複雑にせず、必要になったときに拡張できる可逆的な形に留める。
- アクセシビリティ、認知負荷、入力ミス、通信遅延を設計上の条件として扱う。
- ユーザーに見せる仕様上の判断と、実装上の機械的な配線を分けてレビューできるようにする。
