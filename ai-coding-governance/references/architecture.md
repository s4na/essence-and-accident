# Architecture reference

メタなアーキテクチャ判断では、個別コードより一段上の「どこまで AI に判断させるか」「どこで止めるか」「どの単位でレビューするか」を扱う。

## 原則

- 実装前に decision diff を出し、コード差分より先に意思決定の差分を承認する
- 承認済み plan から逸脱する新しい判断が出たら、実装を止める
- 境界、層、抽象化、永続化、状態、依存を増やす判断には立証責任を置く
- local consistency を一般的ベストプラクティスより優先する
- 可逆性を優先し、後戻りしづらい判断は小さな実装に混ぜない
- コミットは AI の作業履歴ではなく、人間がレビューできる意味単位にする

## decision diff で確認すること

- 新しい概念・境界・責務が増えるか
- 後戻りしづらい判断があるか
- 既存パターンから逸脱する箇所があるか
- 機械的変更と設計判断が混ざっていないか
- 同じコードを複数回レビューさせる commit / diff になっていないか
