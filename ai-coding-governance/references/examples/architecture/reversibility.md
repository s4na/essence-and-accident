# 可逆性を優先するアーキテクチャ判断: 後戻りしやすい形に留める

## 要件

β ユーザーだけに新しいヘルプ文言を表示したい。

## やらないこと

- 永続的な feature flag platform を作らない
- ユーザー segment テーブルを作らない
- 権限・課金・AB test の汎用基盤を混ぜない

## decision diff

- 新しい概念: なし、または既存の beta 判定のみ
- 採用する実装: 既存の `beta?` 判定がある場合だけ局所分岐する
- 承認が必要な判断: beta 判定が存在しない場合は実装停止し、判定の持ち方を相談する

## 普通の実装の全体像

```erb
<!-- app/views/help/show.html.erb -->
<% if current_user.beta? %>
  <p>新しいヘルプ文言です。</p>
<% else %>
  <p>ヘルプ文言です。</p>
<% end %>
```

## レビュー観点

- 削除するときに 1 箇所で戻せるか
- 実験的な表示要件を恒久的な基盤にしていないか
- beta 判定が既存概念として存在するか
