# 承認後に逸脱しない: 新しい判断が出たら止まる

## 要件

承認済み plan: 既存プロフィール画面に `bio` を表示する。

## 実装中に発見したこと

`bio` が空のユーザーがいる。

## やってはいけないこと

- 勝手に `bio_required` validation を足さない
- 勝手に migration で default を入れない
- 勝手に onboarding flow を変えない

## 普通の停止メッセージ

```text
実装中に追加判断が必要な点が見つかりました。

承認済み plan では bio を表示するだけでしたが、bio が空の場合の表示仕様が未定義です。
選択肢:
1. 空なら何も表示しない
2. 空なら「未設定」と表示する
3. bio を必須化する（DB / validation 変更が必要）

最小差分は 1 または 2 です。どちらで進めますか。
```

## レビュー観点

- 承認済み plan にない validation / migration / flow 変更をしていないか
- 不明点を実装で勝手に決めていないか
