# Examples

このディレクトリは、`ai-coding-governance` の「普通のルールに従うとどういう全体像になるか」を示す例です。

目的は、正解の設計パターン集を作ることではありません。AI が過剰に自由な設計空間へ出ないように、よくある変更を **最小概念差分**・**既存パターン優先**・**decision diff 先行**で扱うとどう見えるかを示します。

## 読み方

各ドキュメントは、次の順番で読みます。

1. 要件
2. やらないこと
3. decision diff
4. 実装の全体像
5. インラインのコード例
6. レビュー観点

コード例はすべて Markdown 内にインラインで置いています。実際のアプリにそのままコピーするためではなく、AI に期待する変更の粒度・責務境界・禁止したい過剰設計を共有するためのものです。
